# Security & Quality Gates - Documentation

## Overview

The Booked authentication system includes comprehensive security scanning and quality gates across local development and CI/CD pipelines.

### Security Layers

```
┌─ Build & Compile ────┐
│  (Catch syntax errors)│
└──────────┬────────────┘
           ↓
┌─ Unit Tests ────────┐
│ (Logic validation)  │
└──────────┬──────────┘
           ↓
┌─ Integration Tests ─┐
│ (Flow validation)   │
└──────────┬──────────┘
           ↓
┌─ Dependency Scan ───┐
│ (Vulnerable packages)
└──────────┬──────────┘
           ↓
┌─ Secret Scan ───────┐
│ (Exposed credentials)
└──────────┬──────────┘
           ↓
┌─ SAST (SonarCloud) ─┐
│ (Code vulnerabilities)
└─────────────────────┘
```

## CI/CD Pipeline

### GitHub Actions Workflow

Located in `.github/workflows/security-gates.yml`

**Triggers:**
- Push to `main` or `develop` branches
- Pull requests targeting `main` or `develop`

**Jobs:**

1. **build-and-test** (runs on Ubuntu)
   - Restores dependencies
   - Builds in Release mode
   - Runs unit tests → integration tests
   - Checks for vulnerable packages
   - Uploads test results as artifacts

2. **security-scan** (runs on Ubuntu)
   - Trivy filesystem scanner (detects vulnerable OS/app packages)
   - GitLeaks secret scanner
   - Results uploaded to GitHub Security tab

3. **code-quality** (runs on Ubuntu)
   - SonarCloud analysis (if SONAR_TOKEN configured)
   - Detects code smells, duplications, security hotspots

### Setting Up GitHub Actions

#### Step 1: Enable Actions in Repository

```bash
# In GitHub web UI: Settings > Actions > Allow all actions
```

#### Step 2: Add Secrets (Optional - for SonarCloud)

```bash
# In GitHub web UI: Settings > Secrets and variables > New repository secret

SONAR_TOKEN=<your-sonarcloud-token>
GITHUB_TOKEN=<auto-generated by GitHub>
```

#### Step 3: Create SonarCloud Project

```bash
# 1. Sign in at https://sonarcloud.io
# 2. Link your GitHub account
# 3. Create organization (e.g., "booked-auth")
# 4. Analyze repository
# 5. Copy project key and token
# 6. Add SONAR_TOKEN to GitHub secrets
```

## Security Scanning Details

### 1. Vulnerability Scanning (`check-vulnerabilities.ps1`)

**What it detects:**
- Outdated NuGet packages with known CVEs
- Example: System.IdentityModel.Tokens.Jwt v7.0.0 (GHSA-59j7-ghrg-fj52)

**How to run:**

```powershell
.\scripts\ci\check-vulnerabilities.ps1
```

**Output:**
```
Project: Booked.Identity.Api
  ⚠️  VULNERABLE PACKAGES FOUND
     > System.IdentityModel.Tokens.Jwt 7.0.0 (use 8.0.1 or later)

❌ SCAN FAILED: Vulnerable packages detected
```

**Remediation:**

```powershell
# Update all packages
dotnet package update

# Or update specific package
dotnet package update System.IdentityModel.Tokens.Jwt --project src/services/identity/Booked.Identity.Api
```

### 2. Secret Scanning (`scan-secrets.ps1`)

**What it detects:**
- API keys, tokens, passwords
- JWT tokens, AWS credentials
- Private key files
- Connection strings with passwords
- Hardcoded secrets

**How to run:**

```powershell
.\scripts\ci\scan-secrets.ps1
```

**Output:**
```
⚠️  SCAN FAILED: Found 1 potential secret(s)

  File: src/services/identity/appsettings.Development.json
  Line: 12
  Type: JWT Token
  Content: eyJhbGciOiJIUzI1NiIs***REDACTED***
```

**Remediation:**
1. Replace hardcoded secret with environment variable
2. Rotate any compromised credentials
3. Add pattern to `.gitignore` if needed
4. Use Azure Key Vault for production

**Safe patterns (excluded from scan):**
- `r4nd0m_dev_secret` (development placeholder)
- `admin123` (test admin password)
- `test_token`, `fake_` (test fixtures)

## Security Best Practices

### For Developers

1. **Before Committing:**
   ```powershell
   # Run local security checks
   .\scripts\ci\ci-pipeline.ps1 -Stage security
   ```

2. **Secrets Management:**
   - ✅ Use `appsettings.Development.json` for dev secrets
   - ✅ Use environment variables for prod secrets
   - ✅ Use Azure Key Vault for sensitive prod data
   - ❌ Never commit real tokens, passwords, or keys

3. **Dependency Updates:**
   - Review update notifications from GitHub Dependabot
   - Update immediately for critical security patches
   - Run tests after updates

### For CI/CD

1. **Automated Checks:** All jobs must pass before merge
2. **Status Checks:** Configure branch protection rules:
   - ✅ security-gates.yml passes
   - ✅ All reviews approved
   - ✅ Branches up-to-date with main

3. **Artifact Retention:** Keep reports for 30 days minimum

## Troubleshooting

### Issue: Build Fails on CI but Works Locally

**Solution:**
- Push only clean, tested code
- Run `.\scripts\ci\ci-pipeline.ps1 -Stage all` before push

### Issue: "Vulnerable Packages Detected"

**Solution:**
```powershell
# Check what's vulnerable
dotnet list package --vulnerable

# Update
dotnet package update

# Verify fixed
.\scripts\ci\check-vulnerabilities.ps1
```

### Issue: Secret Scan Reports False Positive

**Solution:**
1. Review detected pattern in scan-secrets.ps1
2. If safe (dev placeholder), add to exclusion list
3. Rerun scan

### Issue: SonarCloud Not Running

**Solution:**
1. Verify SONAR_TOKEN is set in GitHub secrets
2. Check sonarcloud.properties is in repo root
3. Verify SonarCloud account has access to organization

## Compliance & Audit

### Audit Trail

- All test runs logged in GitHub Actions
- Each run includes:
  - Timestamp
  - Triggering commit/PR
  - Test results (passed/failed)
  - Security scan results
  - Artifacts (reports)

- Test reports: 30 days
- Scan reports: 30 days
- Build artifacts: 5 days
